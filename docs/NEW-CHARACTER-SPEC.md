# 新增角色制作规范

版本：`1.0`  
适用范围：为《蛐蛐乱斗》设计、生成、裁切、接入和验收一个新角色。  
关联文档：[设计总规范](./DESIGN-SPEC.md)、[角色接入规范](./CHARACTER-SPEC.md)、[贴图目录规范](./SPRITE-DIRECTORY.md)、[角色设计稿](./templates/CHARACTER-BRIEF.md)、[角色配置模板](./templates/character.template.json)。

这是一份从“想法”到“可以上线”的交付标准。新增角色必须先完成设计稿，再制作素材和配置，最后通过测试与浏览器检查。不能先把一张大图塞进代码，再用缩放、镜像或错误裁切掩盖缺少动作的问题。

## 1. 角色必须遵守的共通规则

所有角色共用移动、防御、闪避、能量、基础拳脚和受击规则。角色差异集中在技能一、技能二和大招；不能为某个角色单独改变基础键位或基础战斗规则。

| 项目 | 固定要求 |
| --- | --- |
| 输入 | P1：WASD + J/K/L/U/I/O；P2：方向键 + 小键盘 1/2/3/4/5/6 |
| 基础动作 | 拳、脚、前＋拳、前＋脚、下＋拳、下＋脚全部存在 |
| 角色技能 | 技能一和技能二各消耗 1 个能量点；大招消耗 3 个能量点 |
| 冷却 | 技能和大招默认没有时间冷却；用能量、前后摇、距离和反制方式平衡 |
| 能量 | 蓄能每满 100 转为 1 点，最多 3 点；释放时扣点，不扣未满蓄能 |
| 防御 | 下方向站防；下＋后方向蹲防；防御默认承受 25% 芯片伤害 |
| 打断 | 技能一/二只有实际带击飞或倒地的命中才能打断技能；大招只能被技能一、技能二或大招打断 |
| 扫腿保护 | 扫倒后的 5 秒内不能再次被扫倒，但仍受伤、硬直、抓取和其他控制 |
| 模拟 | 固定 60Hz；所有时间字段使用帧，不使用浏览器毫秒作为战斗数据 |
| 部署 | 静态网页本地运行，不依赖后端、账号或网络接口 |

角色必须有一个主定位和一个明确弱点。推荐从远程牵制、近身压制、抓取、对空、突进、范围控制中选择主定位，再写出至少一种可靠反制方式。角色不能同时拥有最佳距离、最佳对空、最佳突进和最佳终结能力。

## 2. 新角色交付包：一共需要什么

### 2.1 必交设计资料

必须提交一份角色设计稿，至少包含：

1. 唯一 `id`、中文名、英文或内部短名、主色和辅助色。
2. 一句话定位、擅长距离、核心玩法、优势和弱点。
3. 角色外形基准图，以及素材来源、授权记录或生成提示词。
4. 基础属性：移动速度、起跳速度、受击框宽高、AI 偏好距离和退避距离。
5. 九个动作槽位的名称、作用、伤害、前摇／有效／后摇、命中效果和反制方法。
6. 技能的音画表现：人物动作、特效层、命中反馈、释放音效和是否有语音。
7. 角色与现有角色的区别，以及不会形成无限压制的限制条件。

设计稿使用 [CHARACTER-BRIEF.md](./templates/CHARACTER-BRIEF.md)，不要直接跳过设计阶段修改 `roster.js`。

### 2.2 必交代码与配置

必须在角色配置中填写以下字段，并通过 `js/character-schema.js`：

```text
id / name / subtitle / description
color / accent
speed / jump / width / height
ai.preferredRange（可选 retreatBelow）
moves.punch / kick / forwardPunch / forwardKick
moves.specialPunch / specialKick / skill / skill2 / super
sprites.SPRITE_STATES 的全部状态
```

九个动作槽位是：

| 槽位 | 玩家输入 | 角色是否可以改基础规则 |
| --- | --- | --- |
| `punch` | J / 小键盘 1 | 不可以，使用共通拳规则 |
| `kick` | K / 小键盘 2 | 不可以，使用共通脚规则 |
| `forwardPunch` | 前＋J / 前＋1 | 不可以，使用共通突进拳规则 |
| `forwardKick` | 前＋K / 前＋2 | 不可以，使用共通飞踢规则 |
| `specialPunch` | 下＋J / ↓＋1 | 不可以，使用共通上勾拳规则 |
| `specialKick` | 下＋K / ↓＋2 | 不可以，使用共通扫腿规则 |
| `skill` | U / 小键盘 4 | 可以设计角色招式 |
| `skill2` | I / 小键盘 5 | 可以设计角色招式 |
| `super` | O / 小键盘 6 | 可以设计角色大招 |

技能字段至少要写清：`startup`、`active`、`recovery`、`damage`、`range`、`box`、`stun`、`knockback`、`cost`、`gain`、`groundOnly`、`ai.role`、`ai.weight`。使用特殊效果时，还要填写对应的 `effect` 参数。

引擎当前支持的效果类型为：

| `effect` | 用途 | 必须额外说明 |
| --- | --- | --- |
| `dash` | 地面突进 | 突进速度、有效距离、打空后的风险 |
| `rise` | 升空或上挑 | 起跳速度、落地时间、对空用途 |
| `projectile` | 气功波、奶蛋等独立物体 | 发射偏移、速度、半径、寿命、分段伤害和躲避方式 |
| `burst` | 自身或落点范围爆发 | `burstRange`、触发帧、是否击飞或倒地 |
| `rush` | 多段突进 | 每段时间、方向和结束位置 |
| `grab` | 地面抓取 | 持续时间、各段时间线、抓空和被打断方式 |
| `global` | 无视水平距离的直接命中 | 目标条件、前摇、是否可防御、唯一命中时机 |

如果需要新的效果类型，必须先改引擎、schema、测试和规范，不能只在角色说明里写一个当前代码不认识的字段。

### 2.3 必交角色贴图

资源必须放在独立目录：

```text
assets/characters/<character-id>/
├── common/
│   ├── atlas.png 或多个动作 PNG
│   └── manifest.json 中登记公共动作
├── skill1/atlas.png
├── skill2/atlas.png
├── super/atlas.png
└── manifest.json
```

角色至少要有以下 **18 个状态／动作映射**：

| 类别 | 必须提供 | 最低帧数 | 推荐帧数 |
| --- | --- | ---: | ---: |
| 公共状态 | `idle` 待机 | 1 | 2–4 |
| 公共状态 | `walk` 行走 | 4 | 6 |
| 公共状态 | `jump` 跳跃 | 3 | 4–6 |
| 公共状态 | `guard` 站防 | 2 | 2 |
| 公共状态 | `crouchGuard` 蹲防 | 2 | 2–3 |
| 公共状态 | `hurt` 受击 | 3 | 3–4 |
| 公共状态 | `knockdown` 倒地过渡 | 3 | 4–6 |
| 公共状态 | `ko` KO 姿态 | 1 | 1–2 |
| 公共状态 | `dodge` 闪避 | 3 | 3–5 |
| 基础攻击 | `punch`、`kick` | 每个至少 4 | 每个 4–6 |
| 方向攻击 | `forwardPunch`、`forwardKick` | 每个至少 4 | 每个 4–6 |
| 下方向攻击 | `specialPunch`、`specialKick` | 每个至少 4 | 每个 4–6 |
| 角色技能 | `skill`、`skill2`、`super` | 每个至少 4 | 每个 6–10 |

按最低数量计算，一个新角色至少需要 **58 个可用动作帧**：公共状态 22 帧、六种基础／方向攻击 24 帧、三个角色技能 12 帧。这个数字是“可以接入”的下限，不能把同一张错误姿势复制成整套动作；正式角色建议 70 帧以上。

每一个攻击动作必须能对应前摇、有效、后摇三个阶段。阶段可以复用某一帧，但必须在 `phases.startup`、`phases.active`、`phases.recovery` 中明确登记。多段技能还要让每个命中点有对应姿势或连续过渡，不得只显示一张静态图。

### 2.4 可选但推荐的展示素材

以下不是战斗运行的硬性必需，但用于让选角和图鉴更完整：

- 1 张透明角色立绘或 512×512 以内的头像，用于角色卡片和详情页。
- 1 张角色名牌或简短定位图标。
- 技能图标或技能预览帧；图鉴只显示技能类型和说明，不显示按键。
- 角色专属粒子、投射物、落点爆炸或音频文件；若不提供，则使用现有 Canvas 特效和共通音效。

如果展示素材和战斗图集不是同一套形象，必须以战斗静立图为基准修正，不能让选角图与实战角色出现明显身材、颜色或脸部差异。

## 3. 贴图生成、裁切与动画硬性要求

### 3.1 生成要求

- 使用透明背景，不带网格、文字、标签、边框、地面阴影或其他角色。
- 每个格子只放一个完整角色，动作和特效不能越过格子边界。
- 默认统一面向右，左向由引擎镜像；如果原图动作方向错误，应重新生成或重新绘制，不能靠多次代码翻转掩盖。
- 全部动作保持同一人物比例、脸型、服装颜色、光照方向和脚底高度。
- 必须保留安全边距，手、脚、头发和特效不能碰到相邻格子。
- 技能特效优先单独由 Canvas 或独立图层绘制，角色图集中只保留人物本体，避免串边。

### 3.2 裁切与基准线

每帧在 `manifest.json` 或动画映射中记录：

```text
src / rect[x,y,w,h] / scale / anchorX / originY
```

`originY` 是裁切矩形内的脚底基准。所有站立、行走、攻击和技能帧的脚底要落在同一条逻辑地面线上。不能使用包含大特效的整帧外接框来自动缩放人物，否则会出现技能时突然变大、缩小或漂浮。

验收时逐帧查看：头顶、双脚、手部、攻击特效和相邻格子边缘。发现白边、透明边、串入下一帧、缺头、第三只手、脚底漂移或人物突然变胖，直接替换错误贴图，不用 CSS 或 Canvas 裁剪继续掩盖。

### 3.3 动作连续性

- 行走必须有左右脚交替和手臂反向摆动，至少有“左脚前、经过、右脚前、经过”四个不同姿态。
- 前进和后退使用同一套行走循环，不能固定一条腿在前，也不能只闪烁同一帧。
- 跳跃至少包含起跳、空中、落地前后过渡；头部和脚不能被裁掉。
- 普攻和技能至少包含蓄势、出手、命中／维持、收招，必要时增加过渡帧。
- 倒地至少包含失衡、下坠、落地、躺倒和起身衔接；不能瞬间切成躺姿。
- 不使用拖影、双重人物或交叉淡化作为动作过渡；过渡必须来自真实姿势帧。
- 角色释放技能时人物大小不能随光效变化；特效图层和人物锚点分离。

## 4. 技能设计标准

每个新技能都必须写一张“招式卡”，包含以下字段：

| 项目 | 必须回答的问题 |
| --- | --- |
| 招式类型 | 近战、投射物、范围、突进、升空、抓取或全屏直接命中？ |
| 目标与距离 | 贴身、中距离、远距离、全屏，还是必须锁定目标？ |
| 时序 | 前摇、有效、后摇各多少帧？多段命中在哪些帧发生？ |
| 伤害 | 单次或分段伤害是多少？所有分段相加是否等于 `damage`？ |
| 控制 | 硬直、击退、击飞、倒地、抓取、破防分别是什么？ |
| 防御 | 能否站防、蹲防、闪避或跳过？芯片伤害是多少？ |
| 打断 | 能打断普通攻击、小技能或大招中的哪一种？自身能否被打断？ |
| 资源 | 消耗 1 点还是 3 点？是否错误地添加了 cooldown？ |
| 风险 | 打空、被跳过、被闪避或距离错误时，对手如何反击？ |
| AI | 哪个距离和战况使用，何时保留能量？ |
| 表现 | 角色动作、特效、命中闪光、音效和语音何时播放？ |

基础数值边界：拳硬直不超过 12 帧，脚不超过 16 帧，方向攻击和技能通常不超过 24 帧，大招不超过 30 帧。技能可以造成高伤害或强控制，但必须用前摇、距离、命中条件或可躲避性提供反制窗口。技能一、技能二的多段攻击不能只靠重复硬直形成无限压制；连续命中必须留出跳跃、闪避、防御或脱身机会。

技能音效一次释放只触发一次。多段伤害可以有命中音效，但不能在每个模拟帧重复播放释放音频。语音、BGM 和大招音效必须在浏览器真实播放测试中确认不是静音、路径错误或被重复触发。

## 5. 音频、特效和 UI 接入

角色专属音频可以复用 `js/audio.js` 的共通事件，也可以新增资源：

- `playMove`：起手／蓄力／挥空，不播放最终命中声。
- `releaseMove`：进入有效阶段时触发一次技能释放音效。
- `impact`：实际命中、格挡、击飞、倒地或抓摔时触发。
- `superStart`：成功发动大招时触发时停、收缩镜头和大招蓄力音效，不额外播报招式名称。

专属音频放在 `assets/audio/`，保持文件名稳定、音量可控、无明显首尾静音、无削波。语音如果加入，必须说明触发时机，避免每一段连击重复播报。

特效按层绘制：

1. 人物层：只画角色本体和必要的动作残留。
2. 攻击／投射物层：画气功波、奶蛋、声波、抓取标记等独立物体。
3. 命中层：画闪光、爆炸、击飞、倒地冲击和震屏。
4. HUD 层：画能量点、连击、锁定准星和播报。

锁定准星、技能预警和命中特效必须在角色图层之上；不会与人物共用一张裁切图。投射物之间默认穿过，不因互相相碰而消失，除非新机制另行定义并完成测试。

## 6. 接入步骤

按下面顺序提交，避免资源、数据和测试互相脱节：

1. 复制 [角色设计稿模板](./templates/CHARACTER-BRIEF.md)，完成定位、优势、弱点和九个槽位。
2. 复制 [角色配置模板](./templates/character.template.json)，填写基础属性、技能和 AI 参数。
3. 建立 `assets/characters/<id>/common`、`skill1`、`skill2`、`super` 四级目录。
4. 生成或绘制动作图集，按动作分类裁切，记录 `manifest.json`、矩形、脚底基准和素材来源。
5. 先把角色加入 `js/roster.js`，再按需要在 `js/animation-data.js` 登记特殊帧序列。
6. 如果增加效果类型、特殊状态、特效层或音频事件，先补 schema、引擎和测试，再接入角色。
7. 更新角色图鉴和 `docs/BATTLE-RULES.md` 的角色清单；未实现的描述必须标记为未实现。
8. 执行自动化测试、构建和浏览器检查；发现错误动作或裁切时替换素材，不用代码缩放或镜像修补。

## 7. 自动化测试要求

新角色至少新增以下测试：

- 九个动作槽位都能从有效输入开始，能量消耗符合 0／1／3 点。
- 技能和大招没有意外 cooldown；受击硬直和倒地期间不能出招。
- 每个技能在预期距离命中，伤害分段总和正确，防御／闪避／跳跃结果正确。
- 击飞、倒地、抓取、破防和技能打断规则符合招式卡。
- 多段攻击不会重复同一命中点，投射物不会在互相接触时错误消失。
- 角色左右朝向、墙角、空中拳脚、扫腿保护和 KO 流程正常。
- AI 可以在合适距离选择技能，不获得额外伤害、生命、能量或无敌。
- 所有 `SPRITE_STATES` 资源存在，图集裁切矩形有效，行走帧至少四帧且不重复。
- 如果有专属声音，测试文件存在、可解码且不是静音；技能释放音频每次只触发一次。

## 8. 浏览器验收清单

在桌面和手机横屏分别检查：

- 选角卡片能显示角色图片、名字和定位；详情页技能说明能滚动。
- P1 和 P2 键位都能触发九个动作；左右朝向和反向移动正确。
- 站立、行走、跳跃、蹲防、受击、倒地、起身和 KO 没有缺帧、白边、串边或人物变形。
- 技能释放时人物比例稳定，特效、锁定准星和投射物层次正确。
- 技能音效、命中音效、语音和地图 BGM 不重复、不静音、不丢失。
- 19.5:9 手机横屏、普通横屏和窄屏下，战斗画布、虚拟摇杆、六个按钮不遮挡角色。
- 结算动画能完成，并可返回选人或重新开战。
- 浏览器控制台没有资源 404、模块加载错误或未处理异常。

```text

[ ] 九个动作槽位全部有配置，技能 cost 为 1/1/3，cooldown 为 0

[ ] 所有图集透明、无网格、无白边、无串格、无错误镜像和人物变形
[ ] 角色与特效分层，脚底基准、人物比例和朝向一致
```
