# 新地图设计与接入规范

本文规定新增战斗地图的设计、资源、配置和验收方式。地图必须服务于战斗可读性；当前项目的地图只改变场景表现和音乐，不改变角色伤害、移动、碰撞或胜负规则，除非同时完成引擎、schema、测试和战斗规则的扩展。

## 1. 地图定位

每张地图必须先写清楚：

- `id`：唯一、稳定、只使用小写字母、数字和短横线。
- 中文名、英文名和一句场景副标题。
- 场景主题、时间和色彩方向。
- 视觉焦点，以及角色站立后仍能清楚辨认的背景层级。
- 是否为纯视觉地图，或明确声明新增的战斗规则。
- 对应 BGM、循环长度和音频来源。

地图名称、缩略图和战斗内背景必须表达同一个主题，不使用与角色或 UI 冲突的高亮色块。

## 2. 默认战斗边界

除非设计稿明确扩展规则，所有地图必须遵守以下公共边界：

- 地面高度、左右边界和可站立区域与标准竞技场一致。
- 不设置平台、斜坡、可破坏物、陷阱或会遮挡判定的前景物。
- 背景装饰不得进入角色受击框或攻击判定框。
- 摄像机只做统一的跟随、时停和大招收缩，不因地图改变角色大小。
- 墙角反推仍按通用战斗规则执行；地图不能提供额外墙角伤害或无限压制。
- 地图不能改变伤害、能量、硬直、倒地、闪避或防御数值。
- 训练地图的网格只用于定位和练习，不提供额外碰撞。

如果确实需要平台或地图机关，必须先在 `DESIGN-SPEC.md` 的变更记录中登记，并新增地图碰撞层、角色状态、AI 逻辑、渲染表现和自动化测试；不能只在素材中画出来。

## 3. 资源结构

新增地图资源放在 `assets/arena/`，推荐结构如下：

```text
assets/arena/
├── <map-id>/
│   ├── background.png       # 远景或完整背景
│   ├── midground.png        # 可选，中景装饰
│   ├── foreground.png       # 可选，只能放在安全遮挡区
│   ├── thumbnail.png        # 选图页缩略图
│   └── manifest.json
└── ...
```

纯 CSS 或 Canvas 绘制的地图可以没有 PNG，但必须在 `manifest.json` 中声明 `renderer: "procedural"`，并保证离线加载。单张完整背景也必须通过 manifest 登记，不能在代码中散落硬编码路径。

### 3.1 Manifest 最小字段

```json
{
  "id": "new-arena",
  "name": "新地图",
  "english": "NEW ARENA",
  "subtitle": "一句场景介绍",
  "renderer": "image",
  "background": "./assets/arena/new-arena/background.png",
  "thumbnail": "./assets/arena/new-arena/thumbnail.png",
  "filter": "none",
  "floor": 0.78,
  "musicId": "new-arena",
  "collision": { "left": 72, "right": 72, "floor": 0.78 }
}
```

`floor` 使用 0 到 1 的画布比例；若使用统一竞技场地面，优先复用当前默认值。`filter` 只能做轻量色调处理，不能依靠极端滤镜掩盖低质量资源。

## 4. 画面与可读性

- 背景应至少区分远景、中景和地面层，避免所有内容在同一深度。
- 地面线必须连续、水平且能看出角色脚底位置。
- 角色所在区域不得出现高频细纹、强闪烁或接近角色轮廓的高对比边缘。
- 角色、投射物、命中特效和 HUD 使用独立绘制层。
- 不使用拖影、残影或让背景造成角色重影的透明叠加。
- 16:9、4:3、窄屏和高 DPI 下，地面与左右边界仍需稳定。
- 缩放场景时保持像素素材整数或近整数比例，避免明显糊边和抖动。

## 5. 音频

每张可选地图必须有独立 `musicId`，并在 `js/audio.js` 的音乐表中登记。BGM 应循环自然，进入比赛时开始或切换，暂停时保持暂停，结算时按当前地图继续或按全局结算规则切换。音频加载失败不能阻止战斗。

地图环境声可以添加，但不能盖过普攻、受击、防御、技能和 KO 播报。音量、静音和首次用户交互策略遵循 [音频说明](./AUDIO.md)。

## 6. 接入流程

1. 在设计稿中写主题、视觉层级、地面位置、边界、BGM 和资源来源。
2. 制作背景和缩略图，检查透明边缘、分辨率、压缩质量和授权记录。
3. 创建地图目录和 `manifest.json`。
4. 在 `js/maps.js` 注册显示元数据和资源路径。
5. 在 `js/audio.js` 注册地图 BGM。
6. 更新地图选择界面、文档和素材说明。
7. 添加资源存在性、地图可选、BGM 可播放和窄屏渲染测试。
8. 运行 `npm test`、`npm run build`，并用浏览器 smoke 检查从选图到战斗和结算的完整流程。

## 7. 地图验收清单

- [ ] `id` 唯一，名称、副标题、缩略图和 BGM 完整。
- [ ] manifest 路径有效，资源可离线加载。
- [ ] 地面高度、左右边界和角色脚底对齐。
- [ ] 背景不会遮挡角色、投射物、判定框或 HUD。
- [ ] 16:9、窄屏和高 DPI 下没有拉伸、溢出或明显抖动。
- [ ] 地图不偷偷改变伤害、移动、能量、硬直或防御规则。
- [ ] BGM 能循环、暂停、切换，且音量与战斗音效平衡。
- [ ] 选图页能显示缩略图，刷新后仍能恢复合法选择。
- [ ] AI、玩家、练习、电子斗蛐蛐和结算流程均可进入该地图。
- [ ] `npm test`、`npm run build` 和浏览器 smoke 通过。

## 8. 当前地图状态

当前地图均为纯视觉地图：夕照天台使用原创背景，午夜天台复用天台布局并使用冷色滤镜，训练空间使用程序绘制网格；霓虹天台、锈炉工厂、月下竹林和奶蛋实验室使用独立原创背景。所有地图共用标准地面和边界，没有平台、陷阱或地图机关。
